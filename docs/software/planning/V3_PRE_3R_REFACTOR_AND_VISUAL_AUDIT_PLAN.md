# Version 3 Pre-3R Program — Architecture Refactor and Planar 2R Visual Audit

**Status:** active program amendment — V3.6A and V3.6B completed; V3.6C active; residual V3.7 drafted / blocked
**Authority:** scoped amendment to `docs/software/V3_PROJECT_PLAN.md` for the pre-3R handoff
**Applies after:** corrected Sprint V3.6 closeout
**Blocks:** architecture-final Sprint V3.7 acceptance and Sprint V3.8 activation
**Program sequence:** Sprint V3.6A (completed) → Sprint V3.6B (completed) → Sprint V3.6C (active) → revised / residual Sprint V3.7
**Note:** A provisional V3.7 implementation and evidence package already shipped ahead of this sequence and is retained; this program now runs as architecture-debt gates before treating 3R as final.

## 1. Decision

Insert three bounded gates between the corrected planar 2R evidence sprint and
the architecture-final planar 3R implementation:

\[
\boxed{
\text{V3.6 corrected 2R evidence}
\rightarrow
\text{V3.6A dimensional-generalization refactor}
\rightarrow
\text{V3.6B planar 2R visual audit}
\rightarrow
\text{V3.6C planar 2R closeout corrections}
\rightarrow
\text{V3.7 planar 3R implementation}
}
\]

V3.6A removes known concrete 2R dependencies from shared architecture. V3.6B
then uses the still-readable 2R case to expose the actual
\(\mathcal U\rightarrow\mathcal Q\rightarrow\mathcal X\) mapping, graph
embeddings, planner traces, and metric calculations in one trial-scoped HTML
artifact. V3.6C corrects the concrete goal-set, provenance, trajectory,
visualization, and metric-interpretation discrepancies found during Gate B
review. V3.7 begins only after all three gates are reviewed.

These are pre-3R implementation gates, not new population studies and not a
reinterpretation of V3.6 evidence.

## 2. Why this program exists

The Version 3 contracts are mostly dimension-independent, but several delivered
implementations still reach through concrete 2R or operating-branch details:

| Current seam | Required boundary |
| --- | --- |
| `OperatingBranchRobotModel` stores `Planar2R` and rejects non-2D `q` | generic kinematic model protocol |
| sampling helpers reach through `robot.branch.certificate` | robot-owned input-domain contract |
| `core.goals` imports planar 2R kinematics and contains 2R IK-family logic | core predicate/generator protocols plus kinematics-specific generators |
| path and Cartesian metrics are recomputed inconsistently or omitted | shared trajectory sampling and metric utilities |
| graph, roadmap, and tree internals expose counts but not audit traces | opt-in, planner-family trace contract |
| existing plots are individual figures | trial-scoped, offline, print-aware HTML assembly |

The refactor must preserve the V3 rule that physical state, task, planner
representation, local motion, objective, planner, and benchmark policy remain
independent.

## 3. Program principles

1. **Close V3.6 first.** Do not edit its frozen result package or regenerate its
   evidence under the refactor.
2. **Refactor before extending.** Shared modules must no longer depend on
   `Planar2R` or a concrete `branch` attribute before planar 3R is added.
3. **Audit, do not infer.** The visual audit is a ten-task implementation review,
   not Monte Carlo, hypothesis testing, or a performance claim.
4. **One trial, one readable unit.** Each HTML trial page contains one shared task
   and one four-bar/gearbox pair. Pooled plots do not replace trial pages.
5. **Trace instrumentation is opt-in.** Normal planner runs do not carry large
   expansion, roadmap, or tree histories.
6. **Reuse the current semantics.** The audit uses corrected V3.6 shared starts,
   the frozen Cartesian goal representation, the current representative
   four-bar, and its span-matched gearbox.
7. **No notebook-only logic.** The report is generated by a versioned command
   from library code and a frozen configuration.

## 4. Gate A — architecture refactor

Sprint V3.6A delivers the following boundaries.

### 4.1 Generic kinematics

Introduce a narrow protocol such as:

```python
@runtime_checkable
class KinematicModel(Protocol):
    @property
    def dof(self) -> int: ...

    def forward(self, q: ArrayLike) -> Pose: ...
    def jacobian(self, q: ArrayLike) -> NDArray[np.float64]: ...
```

`Planar2R` implements the protocol. `OperatingBranchRobotModel` stores a
`KinematicModel | None`, validates that its DOF matches the transmission output
dimension, and delegates FK/Jacobian operations without testing for shape
`(2,)`.

A visualization-only protocol may separately expose link polylines. Rendering
methods do not become requirements of the core robot contract.

### 4.2 Robot-owned input domain

Introduce an `InputDomain` or equivalent object owned by `RobotModel`:

```python
@dataclass(frozen=True, slots=True)
class InputDomain:
    lower: NDArray[np.float64]
    upper: NDArray[np.float64]
    periodic: tuple[bool, ...]
```

The initial certified monotonic branch returns a bounded, nonperiodic box.
Sampling planners and the OMPL state-space adapter consume this object rather
than reaching through `robot.branch.certificate`.

The domain contract must leave room for later periodic/noninjective input axes
without activating that work now.

### 4.3 Goal-generator separation

Keep these in core:

- `GoalConstraint`;
- `GoalResidual`;
- `GoalStateGenerator`;
- `GoalSamplingRequest`;
- generic exact-output and task-space predicates.

Move planar 2R IK and elbow-family classification to a kinematics-specific
module. `core.goals` must not import `Planar2R` after the refactor.

### 4.4 Shared trajectory metrics

Add one shared utility that samples or consumes a `Trajectory` and reports:

\[
L_U=\sum\|\Delta u\|_2,
\qquad
L_Q=\sum\|\Delta q\|_2,
\qquad
L_X=\sum\|\Delta x\|_2,
\]

plus endpoint residuals and waypoint count. Continuous-motion integrations keep
their own declared values; the utility does not silently replace them with
endpoint formulas.

Existing frozen evidence remains unchanged. New metrics are opt-in until a new
result artifact is generated.

### 4.5 Dimension audit

Add a synthetic three-dimensional affine transmission/kinematics fixture to
exercise:

- physical-state construction;
- uniform input sampling;
- native PRM and RRTConnect;
- OMPL state-space round trip when available;
- dimension-independent tensor topology and 26-connected neighbors;
- serialization and result metrics.

This fixture is an architecture test only. It is not the planar 3R robot and
carries no V3.7 scientific result.

## 5. Gate B — planar 2R visual audit

### 5.1 Frozen audit corpus

Use one representative paired mechanism from the current V3 smoke/evidence
stack:

- two identical crank-rocker axes with
  \(a=1.0, b=2.5, c=2.0, d=2.0\), selected on certified monotonic branches;
- the current span-matched equivalent gearbox;
- shared planar 2R forward kinematics with \(L_1=L_2=1\).

Use exactly ten corrected V3.6 tasks:

```text
near_0, near_1, near_2, near_3, near_4,
far_0,  far_1,  far_2,  far_3,  far_4
```

Each task retains:

- one shared resolved `start_q` and Cartesian start tip;
- mechanism-specific certified `start_u` realizations;
- the physical Cartesian disk predicate;
- the frozen center-plus-eight-near-boundary point representation;
- the same candidate ordering and provenance across mechanisms.

The audit uses one stochastic seed (`7`) and no repetitions. Failures remain in
the report; tasks are not silently replaced.

### 5.2 Planner set

Run only already-delivered planners:

1. input-linear direct reference;
2. output-linear direct control;
3. eight-connected integrated-cost lattice Dijkstra;
4. eight-connected integrated-cost lattice A*;
5. native PRM, seed 7;
6. native RRTConnect, seed 7;
7. OMPL PRM, seed 7, when available;
8. OMPL RRTConnect, seed 7, when available.

Use a dedicated audit lattice, default `32 × 32`, to make topology and expansion
animations readable. This is audit resolution, not evidence resolution.

### 5.3 Mapping and metric views

For each mechanism and joint axis, plot:

- \(q_i(u_i)\);
- \(u_i(q_i)\);
- \(dq_i/du_i\);
- certified input/output limits;
- the path's start, selected goal, and traversed range.

For every shared Q-lattice edge \(e\), calculate declared local-motion arc
lengths:

\[
w_U(e)=\int_e \|\dot u\|_2dt,
\qquad
w_Q(e)=\int_e \|\dot q\|_2dt,
\qquad
w_X(e)=\int_e \|\dot x\|_2dt.
\]

Render the same graph in three coordinate embeddings:

1. **Q layout:** \((q_1,q_2)\);
2. **U layout:** \((u_1,u_2)\);
3. **X layout:** end-effector \((x,y)\), retaining graph adjacency even where
   the embedding overlaps or folds.

On the Q layout, provide separate edge-color panels for \(w_U\), \(w_Q\), and
\(w_X\). For output-linear edges on a shared Q graph and common arm kinematics,
\(w_Q\) and \(w_X\) must agree across the mechanism pair within tolerance;
\(w_U\) is the mechanism-dependent quantity.

Also show transmission-stretch fields without collapsing direction:

\[
s_{Q/U}(e)=\frac{w_Q(e)}{\max(w_U(e),\epsilon)},
\qquad
s_{U/Q}(e)=\frac{w_U(e)}{\max(w_Q(e),\epsilon)}.
\]

The static print panels are the authoritative review views. Interactive or
animated assets supplement them and must never be the only place where a result
is visible.

Also report the local differential chain

\[
J_{u\rightarrow x}(u)=J_f(q)J_g(u)
\]

and the actuator-travel metric expressed on Q,

\[
M_Q(q)=J_{g^{-1}}(q)^\mathsf T J_{g^{-1}}(q).
\]

For the independent-axis 2R case, plot useful scalar fields such as diagonal
metric entries, trace/determinant, and condition number. Differential fields are
interpretive diagnostics; integrated edge weights remain the planner truth.

### 5.4 Planner traces and animation

Add an opt-in audit trace sink outside `PlanningProblem` and outside the common
`PlanningResult` schema. Family-specific payloads are allowed under one envelope:

```python
@dataclass(frozen=True, slots=True)
class PlannerTraceEvent:
    family: str
    phase: str
    step: int
    event_type: str
    payload: Mapping[str, JSONValue]
```

Minimum traces:

- graph search: expanded node IDs in order, generated count, final path;
- PRM: sampled/accepted vertices, accepted edges, query attachments, Dijkstra
  expansion order, final path;
- RRTConnect: accepted vertices and parent edges in insertion order, tree
  identity, connection event, final path;
- OMPL: final `PlannerData` snapshot and path; no false claim of stepwise history
  when the binding does not expose it.

Create one combined lattice-search animation per trial showing
four-bar/gearbox × Dijkstra/A* in synchronized percentage-of-trace frames, with
actual expansion counts annotated. Provide static 0/25/50/75/100-percent
contact sheets for printing. Roadmap/tree growth animations are required for
three designated representative trials (`near_0`, `near_3`, `far_2`) and static
final traces for all ten trials.

### 5.5 Trial-scoped HTML

Generate an offline report under:

```text
results/v3_review/v3_6b_planar2r_visual_audit/
├── index.html
├── manifest.json
├── architecture.html
├── summary.json
├── assets/
└── trials/
    ├── near_0/index.html
    ├── ...
    └── far_4/index.html
```

The index contains only:

- audit scope and non-claim statement;
- configuration/provenance;
- a compact trial navigation table;
- a compact paired-metric summary.

Each trial page is a self-contained reading unit:

1. task and candidate-set definition;
2. shared-Q / mechanism-specific-U invariants;
3. gearbox and four-bar mapping panels;
4. Q/U/X graph embeddings and edge-weight fields;
5. planner traces and animations;
6. U, Q, and Cartesian path plots with manipulator poses;
7. planner metrics by mechanism;
8. paired differences and implementation observations;
9. raw JSON links.

No chart combines unrelated trials in the trial body. Print CSS inserts a page
break between major sections, hides live animations, and substitutes contact
sheets. The report has no CDN or network dependency.

### 5.6 Core metrics

Common metrics:

- status and ADR-026 task class;
- selected goal sample ID and IK family;
- direct represented-goal reference cost;
- planner suboptimality;
- separate \(L_U, L_Q, L_X\) components;
- transmission stretch \(L_Q/L_U\) and inverse effort \(L_U/L_Q\), with guarded denominators;
- configured diagnostic composite scores with every component and normalization exposed;
- waypoint count;
- final Cartesian residual;
- total/setup/preprocess/query/postprocess time;
- state and motion validity checks.

Graph metrics:

- expansions, generated, stale/reopened entries;
- reachable nodes and expansion fraction;
- path edges;
- goal-cost-basin fraction \(\beta\);
- A* expansion reduction relative to Dijkstra;
- exact-start/goal overlay diagnostics.

Roadmap metrics:

- requested/accepted samples;
- vertices;
- attempted/accepted edges;
- query attachments;
- roadmap-search expansions.

Tree metrics:

- iterations;
- extension attempts;
- accepted states;
- nearest-neighbor operations;
- start/goal tree sizes;
- connection step.

Paired quantities use one frozen sign convention:

\[
\Delta z=z_{\mathrm{fourbar}}-z_{\mathrm{gearbox}}.
\]

Report absolute differences before ratios.

Any composite score is diagnostic and configuration-defined:

\[
J_{\boldsymbol\alpha}
=
\alpha_U\widehat L_U
+
\alpha_Q\widehat L_Q
+
\alpha_X\widehat L_X.
\]

The audit config owns the normalization references and weights. Every HTML table
shows the unnormalized components beside the composite. V3.6B does not optimize
or rank mechanisms using a hidden composite objective.

## 7. Required invariants

1. Paired mechanisms have identical Q nodes, Q adjacency, shared start Q, start
   tip, physical goal predicate, represented Cartesian points, candidate Q
   ordering, and planar FK.
2. Every stored physical state passes `robot.validate_state`.
3. For shared output-linear edges, paired \(w_Q\) and \(w_X\) agree within
   tolerance.
4. Mechanism-dependent \(w_U\) is calculated from the declared local motion,
   not inferred from plot geometry.
5. Dijkstra and A* agree on the chosen lattice goal-set cost.
6. Direct input-linear cost is a lower bound for successful planners against the
   same represented goal set, within numerical tolerance.
7. Every HTML asset is listed in the manifest and every relative link resolves.
8. Every trial page contains both mechanisms; no mechanism is omitted because a
   planner failed.
9. Audit trace mode does not change solver path, cost, status, or ordinary
   instrumentation.
10. Frozen V1, V2, V3.5, and V3.6 tests remain green.

## 8. Review questions before V3.7

1. Is the current Q lattice truly shared, or do any planners regenerate task
   geometry per mechanism?
2. Do the U embeddings visibly explain the mechanism-specific actuator cost?
3. Are \(w_Q\), \(w_U\), and \(w_X\) being calculated from the intended local
   motion rather than endpoint shortcuts?
4. Does A* reduce exploration for the right reason, and does its heuristic remain
   a lower bound to the represented goal set?
5. Do PRM and RRTConnect preserve exact starts and the same frozen goal
   candidates?
6. Are differences in selected goal states visible and correctly attributed to
   mechanism-aware cost or planner suboptimality?
7. Do the report and code architecture make every U→Q→X transition auditable?
8. Are any shared modules still 2R-specific after V3.6A?

The completed findings are recorded in
[`V3_6B_GATE_B_REVIEW_FINDINGS.md`](../architecture/notes/V3_6B_GATE_B_REVIEW_FINDINGS.md).
Questions 4–7 produced V3.6C closeout blockers; questions 1–3 and 8 passed with
explicit planner-family or audit-only qualifications.

## 9. Program exit criteria

The pre-3R program passes only when:

1. corrected V3.6 evidence is formally closed and preserved;
2. Sprint V3.6A refactors land with no frozen-evidence regression;
3. the ten-trial V3.6B report is generated from a clean revision;
4. the Gate B review is completed and its discrepancies are assigned to V3.6C;
5. V3.6C delivers true represented-goal parity, retained selected-goal
   provenance, consistent physical residuals, continuous local-motion path
   evaluation, native U/Q/X trace projections, and interpretable actuator-metric
   fields;
6. the new V3.6C report is generated without overwriting frozen V3.6/V3.6B
   artifacts and all closeout invariants pass;
7. the revised V3.7 contract is accepted against the closed 2R architecture;
8. ACTIVE_SPRINT separately activates V3.7.

## 10. V3.6C closeout amendment

Sprint V3.6C is a bounded correction sprint, not a third 2R evidence campaign.
It retains the ten-task audit corpus and mechanism pair, fixes common planner and
result contracts, and writes a new review package under
`results/v3_review/v3_6c_planar2r_closeout/`.

Its authoritative decisions are recorded in
[`V3_6C_CLOSEOUT_DECISIONS.md`](../architecture/notes/V3_6C_CLOSEOUT_DECISIONS.md).
The native PRM remains a roadmap-family control; a separately labeled frozen
shared-Q sampled roadmap isolates mechanism-specific graph weights. U is the
authoritative physical-state view for native roadmap/tree planners, with Q and X
rendered as synchronized projections of the same states and continuous edges.
